# Lex Trust v2 Production

هذه النسخة مهيأة للاستخدام الإنتاجي أكثر من النسخة التجريبية الأولى. لا تستخدم بيانات قضايا حقيقية قبل إكمال إعداد PostgreSQL والتخزين الخارجي S3/R2 والبيئة السرية في Render.

## ما تغير في v2

- PostgreSQL بدل ملف JSON محلي.
- كلمات المرور مشفرة بـ bcrypt.
- جلسات المستخدمين محفوظة في PostgreSQL وليست في ذاكرة السيرفر.
- حماية CSRF + Helmet + Rate Limit.
- إقفال الحساب 15 دقيقة بعد 5 محاولات دخول فاشلة متتالية.
- سجل Audit Log للدخول، إنشاء القضايا، تغيير الصلاحيات، التعيين، رفع/تحميل الأدلة، الرسائل، وتغيير الحالة.
- المالك يحدد الصلاحيات التي يمنحها لكل مستخدم، وليس كل الصلاحيات تلقائيًا.
- العميل يرى قضاياه فقط، والموظف يرى القضايا المسندة إليه، والمالك يرى الجميع.
- الملاحظات الداخلية لا تظهر للعميل.
- المرفقات لا تكون Public؛ تنزيلها يمر عبر فحص صلاحية ثم رابط S3 مؤقت.
- رفع المرفقات محصور بالمالك كما طلبت.
- حد الملف 15MB وأنواع الملفات JPG/PNG/WEBP/PDF.
- جاهز لـ Render من خلال `render.yaml`.

## مهم جدًا قبل القضايا الحقيقية

Render Web Service لديه قرص مؤقت، لذلك في Production الكود يرفض التشغيل إذا كان `STORAGE_DRIVER` ليس `s3`. استخدم AWS S3 أو Cloudflare R2 أو مزود S3 متوافق لحفظ الصور وPDF بعيدًا عن قرص Render.

## أسهل رفع على Render

### 1) ارفع المشروع إلى GitHub

أنشئ Repository خاص Private ثم ارفع محتويات مجلد `lextrust_app_v2_production` بالكامل.

### 2) Render Blueprint

في Render:

1. New > Blueprint.
2. اختر مستودع GitHub.
3. Render سيقرأ `render.yaml` وينشئ Web Service وقاعدة PostgreSQL.
4. قبل Deploy أدخل المتغيرات التي عليها `sync: false`.

المتغيرات المطلوبة:

- `OWNER_PASSWORD` كلمة مرور قوية جدًا للمالك (يفضل 16+ حرفًا).
- `S3_ENDPOINT`
- `S3_BUCKET`
- `S3_ACCESS_KEY_ID`
- `S3_SECRET_ACCESS_KEY`

`SESSION_SECRET` يتم توليده تلقائيًا في Blueprint.

### 3) Cloudflare R2 (مقترح للتخزين)

أنشئ Bucket خاص Private في Cloudflare R2 ثم أنشئ API Token بصلاحية Object Read & Write لهذا الـBucket فقط.

القيم عادة:

- `STORAGE_DRIVER=s3`
- `S3_ENDPOINT=https://<ACCOUNT_ID>.r2.cloudflarestorage.com`
- `S3_REGION=auto`
- `S3_BUCKET=اسم-البكت`
- `S3_ACCESS_KEY_ID=...`
- `S3_SECRET_ACCESS_KEY=...`

لا تجعل الـBucket Public. التطبيق يولد رابط تنزيل مؤقت فقط بعد التحقق من صلاحية المستخدم.

### 4) أول دخول للمالك

القيم من Environment:

- Username = قيمة `OWNER_USERNAME` (الافتراضي في Blueprint هو `owner`).
- Password = قيمة `OWNER_PASSWORD` التي وضعتها.
- Phone/Email = `lex.trust.sa@gmail.com` ما لم تغير `OWNER_CONTACT`.

لا توجد كلمة مرور افتراضية صالحة في Production؛ التطبيق يرفض التشغيل إذا تركتها دون إعداد.

## التشغيل محليًا للتجربة

تحتاج PostgreSQL محليًا. انسخ `.env.example` إلى `.env` وعدّل `DATABASE_URL`، ثم:

```bash
npm install
npm start
```

في Local Development يمكن أن تستخدم:

```env
STORAGE_DRIVER=local
```

لكن هذا للتجربة فقط، وليس للقضايا الحقيقية على Render.

## ربط الدومين

بعد نجاح النشر على Render وظهور رابط مثل:

`https://lextrust.onrender.com`

اذهب إلى Render > Service > Settings > Custom Domains وأضف الدومين الذي تملكه، ثم انسخ سجلات DNS التي يعطيك Render إلى مزود الدومين. بعد التحقق سيفعل Render شهادة HTTPS تلقائيًا.

## النسخ الاحتياطية وحماية البيانات

قبل الاستخدام الفعلي للقضايا:

- فعّل خطة PostgreSQL فيها Backups مناسبة لاحتياجك.
- فعّل Versioning/Lifecycle أو نسخة احتياطية للمرفقات في S3/R2.
- لا تشارك مفاتيح Environment أو `.env` مع أي شخص.
- أنشئ حسابًا منفصلًا لكل موظف ولا تشارك حساب المالك.
- راجع متطلبات نظام حماية البيانات الشخصية السعودي (PDPL) ومكان تخزين/معالجة بيانات العملاء، خصوصًا إذا كان مزود الاستضافة أو التخزين خارج المملكة.
- يفضل إجراء اختبار أمني ومراجعة قانونية/خصوصية قبل إدخال أدلة أو وثائق حساسة حقيقية.

## الصلاحيات الموجودة

- `view_all_cases` عرض جميع القضايا.
- `manage_cases` تغيير حالة القضايا المسندة للموظف.
- `respond_chat` الرد على المحادثات.
- `assign_cases` صلاحية إدارية محفوظة للتوسع؛ التعيين الحالي للمالك فقط.
- `manage_users` صلاحية إدارية محفوظة للتوسع؛ إدارة الصلاحيات الحالية للمالك فقط.
- `view_audit` صلاحية محفوظة للتوسع؛ سجل التدقيق الحالي للمالك فقط.

## ملاحظة أمنية

هذه النسخة تحسن الأساس الأمني بشكل كبير، لكن لا يوجد مشروع ويب يمكن وصفه بأنه آمن 100% بدون إعداد البنية التحتية بشكل صحيح، تحديث الاعتمادات، إدارة الأسرار، النسخ الاحتياطية، ومراجعة أمنية دورية.

## تحديث v2.1 — تفاصيل صاحب القضية
- تمت إضافة حقل الاسم الكامل عند إنشاء الحساب.
- تمت إضافة زر «عرض التفاصيل» بجانب كل قضية.
- نافذة التفاصيل تعرض اسم صاحب القضية، اسم المستخدم داخل الموقع، البريد/الجوال، رقم الحساب، نوع الحساب، تاريخ التسجيل، رقم القضية، حالتها، الموظف المسؤول، وتواريخ القضية.
- قواعد البيانات الحالية تُحدّث تلقائيًا بإضافة عمود `full_name` دون حذف البيانات الموجودة.
- المستخدمون المسجلون قبل هذا التحديث سيظهر اسمهم الكامل «غير مضاف» إلى أن يتم توفيره لاحقًا.
